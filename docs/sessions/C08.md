## Punt 1: sounddevice, sí o no

**No.** La roda de Windows de `sounddevice 0.5.6` (la de `uv.lock`, `sounddevice-0.5.6-py3-none-win_amd64.whl`,
SHA-256 `7f4162f5…f4`) porta `_sounddevice_data/portaudio-binaries/libportaudio64bit.dll`, i:

- la DLL diu `PortAudio V19.7.0-devel`, i el flux de compilació que l'acompanya
  (`portaudio-binaries/.github/workflows/build-libs.yml`) fa `checkout` de PortAudio a `ref: v19.7.0` (abril del 2021);
- el loopback de WASAPI (cada sortida també com a entrada "… [Loopback]" i la funció `PaWasapi_IsLoopback`) es va
  afegir a PortAudio **després** de la 19.7.0: la DLL no conté ni el text `Loopback` (ni ASCII ni UTF-16) ni aquesta
  funció; les funcions `PaWasapi_*` que exporta són les de la 19.7.0;
- l'API de Python tampoc no en té res: `sounddevice.WasapiSettings(exclusive, auto_convert, explicit_sample_format)`.

Per tant, amb sounddevice només es podrien gravar les entrades (micròfon, línia), no el so de l'ordinador. Comprovat
mirant els fitxers de la roda (no cal Windows per saber-ho: les sortides no hi apareixeran mai com a entrades).

Alternativa descartada: compilar una DLL de PortAudio nova (de la branca principal, amb loopback) i fer que sounddevice
la carregui. Funcionaria, però vol dir mantenir una compilació de C pròpia per a Windows; és més feina i més risc que
qualsevol de les dues opcions de sota.

## Proposta: dependència nova (pendent de l'usuari, regla 10)

| | **B. `soundcard`** (recomanada) | C. `PyAudioWPatch` |
|---|---|---|
| Versió (PyPI, 25/10/2026) | `0.4.6` (12/04/2026) | `0.2.12.9` (06/10/2026) |
| Llicència | BSD-3-Clause | **Apache-2.0** (el pla, §1 i §3.1, diu MIT per error) |
| Mida | roda universal de 44 KB, Python pur | roda de 100 KB per versió de Python (`cp312-win_amd64`), amb una PortAudio pròpia compilada a dins |
| Dependències | `numpy` i `cffi`, que ja hi són (`cffi` el porta sounddevice): **res més** | cap |
| Com grava el so de l'ordinador | `soundcard.all_microphones(include_loopback=True)` / `get_microphone(id, include_loopback=True)`: parla directament amb WASAPI (`mediafoundation.py`) amb `cffi` | PortAudio amb loopback: les sortides surten com a entrades "[Loopback]" |
| PyInstaller | porta el seu ganxo (`soundcard/__pyinstaller/hook-soundcard.py`, que hi afegeix els `.h`) | binari propi; caldria provar-lo |
| Altres | Mateixa API per a sortides (loopback) i entrades (G6) | Duplica PortAudio (el de sounddevice continua per a la previsualització) |

**Recomanació: `soundcard 0.4.6`** (com ja deia el pla, opció B): és petita, sense dependències noves, amb llicència
permissiva i preparada per a PyInstaller. Si l'usuari l'aprova:

1. `pyproject.toml` i `uv.lock`: `soundcard==0.4.6` (fixada, com yt-dlp). Cap mòdul de `src/` la importa fins al C09.
2. `tools/prova_gravacio.py`, `packaging/ProvaGravacio.spec` i el treball `prova-gravacio-windows` de la CI (ZIP
   `ProvaGravacio-win64`), amb les proves de `tests/unit/test_prova_gravacio.py` (backend fals), tal com diu el prompt.
3. A la prova del PC, a més dels punts 2–7, mirar dues coses de `soundcard` que no es poden veure des d'aquí:
   - si WASAPI deixa de lliurar blocs quan no sona res (el loopback no envia paquets en silenci): l'script ha de
     distingir "silenci" de "blocs perduts";
   - si cal inicialitzar COM al fil de captura (el C09 grava en un fil a part).
